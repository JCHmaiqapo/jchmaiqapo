conda理解

此文记录，工具——conda的介绍及个人理解及操作，以anaconda为主体

1.为什么要用conda，conda是什么

使用python完成项目，会包含python版本 各种调用包 等内容，但不同项目需要的资源不同，所有资源都被全局可访问的话，不只是冗余，更关键的问题是互相冲突。因此最好每个项目建立一个独立的环境，安装该项目special的资源（无论python还是包）。如何实现？建立虚拟环境，就是conda的功能。

以下来自bing搜索——conda是什么
跨平台的包管理和环境管理工具
Conda 是一个跨平台的包管理和环境管理工具，专为简化复杂依赖关系和隔离多项目环境而设计，尤其适用于科学计算、数据分析及机器学习领域。 它支持多语言库的安装，通过预编译二进制包加速依赖处理，允许用户创建独立环境以灵活切换不同版本的Python和工具库，有效解决版本冲突问题，确保项目间的环境隔离与跨平台一致性，成为管理多版本依赖和协作开发的强大工具。

conda不只用于python，不过我的学习主要以python为主。以上内容，大意即conda可创建多个独立的环境，管理包与环境。本质是一个管理工具。

2.Anacoda是什么

Anaconda就是可以便捷获取包且对包能够进行管理，包括了python和很多常见的软件库和一个包管理器conda。常见的科学计算类的库都包含在里面了，使得安装比常规python安装要容易，同时对环境可以统一管理的发行版本。

3.个人理解

安装的过程省略。如果安装了anaconda，在本机，会发现以下软件：
anaconda navigator（如果下载的miniconda可能没有，不过可以通过conda指令补装）
anaconda prompt
anaconda powershell prompt

其中navigator是可视化的操作界面，新手友好，但是他在执行某些操作，比如查看某个环境的包时，结果其实跟终端（下面要讲）一样，而速度上相差甚远，所以如果想进阶，还是尽量使用终端操作
prompt与powershell prompt，都是终端，只不过前者底层为CMD，后者为PowerShell。虽然叫prompt，但是prompt只是一行命令提示符，并不是实际程序。下面先解释一下终端与shell：
Terminal（终端） 是窗口，Shell 是内核翻译官，Prompt 是 Shell 打印出来的提示文字

Terminal 终端（载体 / 窗口）

作用：负责显示文字、接收你的键盘敲击，不执行命令。

Shell 壳（命令解释器，真正干活的程序）

作用：读懂你敲的命令，交给操作系统内核执行，拿到结果返回。运行在 Terminal 里面。

Prompt 命令提示符（仅仅是一段文本）

作用：Shell 打印出来的提示字符串，告诉你：我就绪，可以输入命令。不是程序。

完整工作流程（一步一步）

  1. 你双击打开终端 Terminal（黑窗口弹出来）
  2. Terminal 自动启动一个 Shell（cmd /powershell/bash）进程
  3. Shell 完成初始化，打印出 Prompt 提示符，等待输入
  1. 你键盘敲入命令 python --version，回车
  2. Terminal 把字符串传给 Shell
  3. Shell 解析命令，调用系统执行，拿到版本结果
  4. Shell 把输出结果交还给 Terminal，打印在屏幕
  5. Shell 再次输出 Prompt，等待下一条输入

##现在说说常见的

类别 名称 说明
Shell（命令解释器，真正执行命令） cmd.exe（CMD） 老 shell；Anaconda Prompt 底层就是它
powershell.exe PowerShell，功能更强
Terminal（窗口载体，只做输入输出显示） wt（Windows Terminal） 新式终端，支持多标签，推荐日常使用
conhost 老旧黑框控制台，尽量不用

现在看，anaconda prompt与powershell prompt就是以两种shell打开的终端，不过他们都会自动打开anaconda安装自动生成的base环境。一般的终端并不会，而且无法使用conda指令（除非修改设置）

那这又是什么原因？来看以下内容

终端、Shell、PATH、Conda 完整闭环

一、核心基础定义

  1. Terminal 终端：窗口载体，只负责显示内容、接收键盘输入，不执行任何命令。Win11 新式为 WT（Windows Terminal），老式为黑框控制台。
  2. Shell 解释器：真正干活的程序，负责解析命令、调用系统执行。常见两种：cmd.exe（CMD）、powershell.exe（PowerShell）。
  3. Prompt 提示符：Shell 输出的提示文本，仅展示状态，不是程序。
  4. PATH 环境变量：系统可执行文件文件夹检索列表。输入外部命令（python/conda/git）时，Shell 按顺序遍历 PATH 目录查找程序，找不到则报错「不是内部命令」。

二、PATH 三层层级（关键，所有问题的根源）

  1. 全局 PATH（系统 PATH + 用户 PATH）
    持久化保存在系统中，新开终端默认自动加载，对所有窗口生效，修改需手动更新/重启终端。
  2. 会话 PATH（核心重点）
    每个独立终端窗口 = 独立隔离的 Shell 会话。
    会话 PATH 基于全局 PATH 生成，支持临时追加修改，仅当前窗口生效，关闭窗口立即销毁，不污染系统全局配置。
  3. 命令分类适配 PATH
  • 内部命令（cd、dir）：内嵌在 Shell 中，无需依赖 PATH，任何窗口都能用。
  • 外部命令（conda、python）：独立程序，必须依赖 PATH 检索才能使用。

三、Anaconda 核心设计逻辑

Anaconda 安装时默认不将 conda 路径写入全局 PATH。
目的：避免全局 Python 环境冲突、污染系统默认环境，防止系统调用异常。
因此：原生全局 PATH 不含 conda 目录，普通终端默认无法识别 conda 命令。

四、两种终端行为差异（完整闭环解释）

  1. 普通 WT/CMD/PowerShell 终端（Win+R、Win+X 打开）
    启动流程：仅启动 Shell（cmd/powershell），无任何额外脚本执行。
    会话状态：会话 PATH = 原始全局 PATH（无 conda 目录）。
    结果：Shell 遍历 PATH 找不到 conda 程序 → 命令报错不可用，无 (base) 环境。
  2. Anaconda Prompt 终端
    本质：不是特殊终端/Shell，只是带自定义启动脚本的快捷方式，底层依旧是 cmd.exe。
    启动流程：
  3. 启动 cmd.exe 生成全新 Shell 会话；
  4. 自动执行 conda 初始化脚本；
  5. 脚本临时追加 conda 相关目录到当前会话 PATH（仅本次窗口生效）；
  6. 自动执行 conda activate base，激活基础环境，提示符显示 (base)。
    结果：当前会话 PATH 包含 conda 目录 → Shell 可检索到 conda 命令，直接可用。

五、Win11 终端打开规则（统一认知）

  1. Win+R 输入 cmd/powershell：指定 Shell，Win11 默认用 WT 作为窗口载体，仅启动原生 Shell，不执行 conda 初始化。
  2. Win+R 输入 wt / Win+X 终端：直接打开 WT 终端，加载 WT 设置的默认 Shell，依旧无 conda 初始化。
  3. Anaconda Prompt 特例：不走 WT，默认唤起老式控制台，自动执行 conda 初始化脚本。

六、核心问题总结（终极结论）

  1. 能否使用 conda 和终端、Shell 本身无关，只取决于：当前 Shell 会话的 PATH 是否包含 conda 目录。
  2. 普通终端不能用 conda：会话 PATH 未追加 conda 路径（无初始化脚本）。
  3. Anaconda 终端能用 conda：启动自动初始化，临时扩容会话 PATH，不修改系统全局配置。
  4. 所有环境差异，本质都是会话 PATH 隔离导致的环境割裂。

七、隐藏风险（必记）

  1. 环境割裂：Anaconda 窗口、普通 WT 窗口 PATH 不同，Python/包环境不一致，代码局部报错。
  2. 版本冲突：若手动把 conda 加入全局 PATH，会抢占系统 Python 优先级，引发全局环境混乱。
  3. 启动损耗：将 conda 初始化写入 Shell 自启脚本，会拖慢终端启动速度。

下面我们来看一些conda指令(来自conda cheat sheet)

来源：https://quickref.cn/docs/conda.html

基础命令

Command Description
conda info 查看 conda 基本信息（版本、源、路径等）
conda update -n base conda 在 base 环境更新 conda
conda install anaconda=2022.05 安装指定 Anaconda 发行版
conda create –name <ENVNAME> 创建新环境
conda activate <ENVNAME> 激活/切换环境
conda env list / conda info -e 列出全部环境
conda list -n <ENVNAME> –show-channel-urls 列出环境包及对应下载源
conda install -n <ENVNAME> <PKG1> <PKG2> 指定环境安装包
conda uninstall <PKGNAME> -n <ENVNAME> 指定环境卸载包
conda update –all -n <ENVNAME> 更新环境内全部包

包与源管理

Command Description
conda list 列出当前环境已安装包
conda list –show-channel-urls 列出包附带源信息
conda update –all 更新当前环境全部包
conda install -c <CHANNELNAME> <PKG1> <PKG2> 从指定源安装包
conda install PKGNAME=3.1.4 安装包指定版本
conda install “PKGNAME>2.5,<3.2” AND逻辑版本约束
conda install “<PKGNAME> [version=’2.5 3.2’]”
conda uninstall <PKGNAME> 卸载当前环境包
conda config –show-sources 查看配置源，从上至下优先级递减
conda config –add channels <CHANNELNAME> 添加源
conda config –remove channels <CHANNELNAME> 移除源

环境操作

Command Description
conda create -n <ENVNAME> python=3.10 指定Python版本创建环境
conda create –clone <ENVNAME> -n <NEWENV> 克隆已有环境
conda rename -n <ENVNAME> <NEWENVNAME> 环境重命名
conda remove -n <ENVNAME> –all 删除环境
conda env remove -n <ENVNAME> 删除环境
conda list -n <ENVNAME> –revisions 查看环境修订历史
conda install -n <ENVNAME> –revision <NUMBER> 环境回滚至指定修订版本

环境导入导出

Command Description
conda env export –from-history > ENV.yml 导出yml，跨平台推荐，仅记录手动安装包
conda env export -n <ENVNAME> > ENV.yml 导出指定环境完整yml
conda list –explicit > ENV.txt 导出精确锁定txt，仅可在相同系统重建
conda env create -n <ENVNAME> –file ENV.yml 从yml重建环境
conda create -n <ENVNAME> –file ENV.txt 从txt重建环境

运维配置

Command Description
conda clean –all 清理缓存安装包，释放磁盘
conda config –show 查看全部conda配置
conda search PKGNAME –info 查看包详细信息
conda xxx –yes 附加–yes自动确认交互，用于脚本
conda config –set auto_activate_base false 关闭终端自动激活base环境

查看命令帮助 & 额外提示

Command Description
conda <COMMAND> –help 获取任意 conda 命令帮助
conda search <PKGNAME> –info 查看软件包详细信息
conda clean –all 清除所有未使用的缓存文件
conda config –show 检查查看 conda 全部配置
conda <COMMAND> ARG –yes 无交互自动确认，脚本使用
conda install PKG1 PKG2 –yes 无交互批量安装包

设置指定环境为默认环境（Linux/macOS）

Command Description
vim ~/.bashrc 使用vim编辑bash配置文件
export PATH=”~/anaconda/envs/ENVNAME/bin:$PATH” 将环境bin目录加入PATH
conda activate ENVNAME 终端启动自动激活目标环境，:wq保存退出vim
source ~/.bashrc 使bashrc配置立即生效
conda config –set auto_activate_base false 关闭终端自动激活base环境
